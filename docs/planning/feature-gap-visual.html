COMPASS / MIGRATION MAP / 2026-11

Compass に入った機能、残っている機能、新しく必要な機能

Wacha（作業管理）の機能は、ほぼ Compass に入っています。残っているのは、agent-foundation の Ralph が持つ「Git 操作・検証・復旧・運用」の部分です。下の表で、移行済みの機能も含めて1行ずつ確認できます。表の最後に、3つのどこにもなく、Compass の目的のために新しく必要になる機能を加えました。

根拠は 2026-11-12 時点のコードです（Wacha 3bcb5bf、agent-foundation b26668c、Compass feat/fit2cloudflare）。「一部」には、細かい差を照合していない項目を含みます。備考にその旨を書いています。「新しく必要」の行は事実の整理ではなく、レビューに基づく提案です。

全体の割合

状態のボタンを押すと、その状態の行だけに絞り込めます。もう一度押すと全件に戻ります。

これから追加するもの

1　最大の塊

Git・GitHub 操作をホスト側で行う仕組み

commit・push・PR 作成・レビューコメント・merge、Role 別の権限、変更できるパスの保護。製品は今、Agent 自身が行う設計です。どちらに置くかを先に決める必要があります。

2

Manager の受入の自動起動

agent-foundation 版は、Reviewer を通過した受入待ちの Task に Manager を起動します。製品の Ralph は相談からの再開だけです。

3

検証の仕組み

実ブラウザ検証（専用プレビュー）、ホスト検証、検証準備の専用コピー。準備スクリプトと手順書は Compass にありますが、動かす側が agent-foundation にあります。

4

復旧と運用

操作エラーの復旧、保留と再評価、Task の依存関係、一時停止・再開・状態表示、Agent の時間切れとプロセス管理。障害史の対処の多くがここに入っています。

5　Server 側

変更を伴わない運用 Task

Wacha の completionMode: evidence（PR を作らず証跡で完了する Task）が、Compass の Work にありません。

6

Knowledge の差分

Wacha の frontend-quality-gates.md と project-defaults.md が Compass にありません。10月以降の Wacha 側の更新（Task の大きさの調整など）も未照合です。

どこにもなく、新しく作るもの

Compass の目的は、Human が方向を与え、Agent が評価まで継続して回すことです。そのために足りない機能を、効果の大きい順に並べました。詳細は表の最後のグループにあります。

まず　1周を閉じる

成果を Outcome へ戻す処理の起動、実 Agent での通し検証

これが無いと評価まで届かず、設計が実際に成り立つかも分かりません。

次に　安全に回す

規則の変更の承認、sandbox と通信の制限、一時停止、費用の上限

Agent だけで回すための土台です。規則の保護は設定だけで始められます。

その次　任せきれるようにする

戻せない操作の前の確認、出どころの区別、証拠の自動取得、重複起動の抑止、通知

常駐で動かし、Human が画面を見ていなくても成り立たせるための機能です。

後で　一緒に作る

対話しながらの開発、目標を一緒に練る場、運用ログの振り返り

Human と Agent が組む場面を広げます。上の土台ができてから進めます。

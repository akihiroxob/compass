# ADR 0011: 相談に任意の回答期限を持たせ、対応待ちを期限だけで並べる

- 状態: 承認
- 対象: Collaboration / Server（MCP・Web API・Web UI）

## 決定

相談（Consultation）に任意の回答期限`dueAt`（epoch ms）を持たせる。Agentが`create_consultation`で時刻帯付きISO 8601として指定し、把握していなければ省略する。未設定は「期限未設定」であり、期限なし・余裕あり・不要を意味しない。作成後は変更しない（期限を変える場合は取消して新しい相談を起票する）。

横断一覧`GET /api/consultations`に`sort`（`updated`既定・`due`）を設ける。`due`は期限が近い順で、期限未設定は期限のある相談の後ろに更新の新しい順で置く。cursorは並びの鍵を含み、ページをまたいでも順序が崩れない。Workspaceの「対応待ち」はHumanが回答しないと進まない`waiting_human`だけを既定とし、`sort=due`で並べる。

影響（`impact`）は自由記述のままで、重さや順位を算出しない。並びの根拠は期限だけであり、画面にもその旨を示す。優先順位を算出する規則は未確定で、確定順位として表示しない。

## 理由

合意UIは「影響と期限を並べて判断する」一覧を求めるが、期限を保持する場所が無く、影響は構造化されていない。影響の重さを推測して順位を付けると未知を確定順位に偽装する。観測可能な期限だけを並びの根拠にし、未設定を後ろに分けることで、並びの理由を説明でき、未知を隠さない。

## 保存と検証

新規DBの`consultation`に`due_at`（null可）を追加し、旧DBからの移行は行わない。`server/tests/workspaceConsultation.test.ts`が期限順・未設定の位置・ページング・不正な期限の拒否を、`server/tests/consultationUi.test.ts`が期限の表示判定を検証する。
